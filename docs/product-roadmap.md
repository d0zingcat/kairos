# Kairos 产品路线图

最后更新：2026-03-11  
负责人：Product / Design / Engineering

## 文档目的

这份文档用于把 Kairos 当前的产品方向整理成可执行的路线图，帮助后续需求讨论、迭代排期和 PR 拆分保持一致。

Kairos 已经具备很扎实的基础能力：

- 书籍 / 音乐 / 影视 / 游戏四类内容记录
- GitHub 风格活动热力图
- Cmd+K 快速录入
- 多用户与隐私控制
- Plaza 公开广场
- Goodreads 导入
- Docker 部署与迁移链路

下一阶段不应该再平均发力地堆功能，而是优先强化核心闭环：

`更快记录 -> 更强反馈 -> 更愿意持续回来`

## 产品判断

Kairos 的目标不该只是一个“记录工具”，而应该逐步变成一个“个人文化生活时间线”。

一个更成熟的 Kairos，应该帮助用户：

- 以极低摩擦记录自己的文化消费活动
- 在每次记录后立刻感受到反馈和进展
- 通过回顾、目标和里程碑建立长期习惯
- 通过 Plaza 发现有趣的人和内容
- 通过公开主页和分享内容表达自己的品味

## 当前阶段判断

### 已有优势

- 已经覆盖记录、编辑、导入、公开展示这条主链路
- 已具备多用户隔离与公开/私密切换能力
- Dashboard、热力图和广场为后续产品深化提供了清晰入口
- 多个外部数据源已接入，具备良好的元数据补全基础

### 当前主要缺口

- 记录能力虽完整，但主入口还不够统一，快速录入没有完全成为高频核心动作
- 用户记录后得到的是“数据落库”，但不是足够强的“即时奖励”
- Dashboard 目前更像存档页，还不够像一个值得反复打开的个人主页
- Plaza 已有雏形，但还偏展示，不够像“可逛、可发现”的内容场
- 留存抓手不足，目标、回顾、连续记录、里程碑体系还不够完整

## 战略优先级

## P0：强化核心闭环

目标：让 Kairos 变得更快、更有反馈、更容易形成习惯。

### 1. 统一 Quick Add 录入体验

把 Cmd+K 和快速录入做成真正的主入口。

范围：

- 统一四类媒体的创建流程
- 输入标题后支持媒体类型智能识别
- 优先展示最近常用的媒体类型和数据源
- 在进入完整编辑前先完成元数据搜索和补全
- 支持状态、评分、日期、简短备注一次录完

价值：

- 降低用户最常见动作的操作成本
- 让快速录入从“便利功能”升级为“核心习惯入口”
- 为后续移动端、轻量输入和自动化采集打基础

### 2. 补齐记录后的即时反馈

每一次成功记录都应该让用户立刻感觉到“有进展”。

范围：

- 保存成功后展示里程碑、连续记录或阶段进展反馈
- 新记录和 Dashboard 摘要卡片联动刷新
- 强化热力图的即时反馈感
- 优先做周/月维度的轻量成就提示

示例：

- 这是你本周完成的第 3 部电影
- 你已经连续记录 5 天
- 你本月累计阅读已超过 1200 页

价值：

- 将情绪奖励直接嵌入记录动作
- 提高再次打开产品的心理动机

### 3. 完整化媒体状态流转

当前记录模型需要从“单次记录”升级为“生命周期记录”。

建议统一状态：

- `wishlist`
- `in_progress`
- `completed`
- `dropped`

后续可扩展：

- `revisiting`
- `rewatching`
- `rereading`

价值：

- 用户能记录过程，而不只是结果
- Dashboard、筛选、统计、回顾和推荐都能因此获得更高信息密度

## P1：让 Dashboard 成为值得回访的个人主页

目标：让用户回来不只是为了录入，也是为了看见自己的生活轨迹。

### 1. 周报 / 月报回顾卡片

回答两个问题：最近发生了什么？它说明了什么？

范围：

- 本周 / 本月完成数量
- 平均评分、活跃天数
- 当期最活跃媒体类型
- 一句自然语言总结

示例文案方向：

- 这个月你最靠近书籍
- 你本周评分最高的是音乐

价值：

- 提升 Dashboard 的回访价值
- 为后续年度回顾和分享能力提供模板

### 2. 目标系统

用轻量目标把“想坚持”变成“看得见的进度”。

范围：

- 按媒体类型设置月目标
- 展示进度条、完成状态、剩余空间
- 视情况增加截止提醒或进度提示
- 与回顾卡片联动展示

示例：

- 本月读完 2 本书
- 本月看完 8 部电影
- 本月玩 10 小时游戏

### 3. 时间维度浏览

让用户按时间回看自己的文化生活。

范围：

- 支持按周 / 月 / 年切换查看
- 优化历史归档体验
- 为年度总结、分享卡片、个人画像做准备

价值：

- 让 Kairos 更像“记忆产品”，而不只是“录入工具”

## P2：把 Plaza 从展示页做成发现页

目标：把 Plaza 从公开动态列表升级成轻量发现层。

### 1. Plaza Feed 排序升级

这是最值得优先投入的 Plaza 能力。

当前判断：

- `src/lib/plaza-feed.ts` 目前仍较轻，适合逐步承接 feed 展示与排序逻辑

范围：

- 在时间倒序基础上引入轻量质量信号
- 提升高评分内容、新鲜内容和媒体多样性的可见度
- 后续可引入兴趣相似度或偏好重合度
- 不再把纯时间倒序作为长期默认策略

首版推荐排序因子：

- 时间衰减
- 评分权重
- 新鲜记录加权
- 稀有度 / 多样性奖励
- 后续互动信号（点赞、收藏、想看）

价值：

- Plaza 会从“有人公开了什么”变成“现在值得逛什么”
- 在不引入重社交治理成本的前提下提升浏览深度

### 2. 丰富动态卡片信息

范围：

- 支持短评或一句话感受
- 展示情绪、类型或推荐意图标签
- 更清晰地说明“为什么这条内容值得被别人看到”

### 3. 先做轻互动，不急着上评论

建议优先级：

- 点赞
- 收藏
- 我也想看 / 想听 / 想玩 / 想读

暂缓评论的原因：

- 治理成本更高
- 通知、审核和滥用处理复杂度更高
- 当前阶段的收益未必高于轻互动

## P3：通过导入与分享获得增长入口

目标：让用户更容易进入 Kairos，也更容易把 Kairos 带出去。

### 1. 扩展导入来源

Goodreads 已经证明导入链路有价值，下一步应该复制到其他高价值来源。

候选来源：

- 豆瓣
- Letterboxd
- Spotify 喜欢内容或榜单
- Steam 库或游玩历史
- Bilibili 收藏或观看记录

### 2. 增强分享能力

范围：

- 月度回顾卡片
- 年度总结海报
- 单条记录分享图
- 公开主页精选模块

### 3. 优化公开主页

范围：

- 最近活动与最近喜爱内容
- 年度 Top 选择
- 品味标签与偏好总结
- 更像个人文化名片的布局设计

## P4：工程质量与可持续演进

目标：让产品能力增长时，工程质量不会成为瓶颈。

### 1. 清理日志方式

- 把剩余 `console.*` 统一替换为 `createLogger`
- 为 Dashboard、Plaza、导入链路统一 namespace

### 2. 补齐高价值测试

优先覆盖：

- server actions
- Plaza feed 排序逻辑
- import parser
- Dashboard 聚合与回顾逻辑

### 3. 做一次权限与隐私审查

- 审查所有公开与多用户相关查询是否严格带 `userId`
- 重点检查 Plaza 与公开主页访问路径
- 验证隐私设置在 Dashboard、广场和公开资料中的一致性

### 4. 做性能与查询优化

- 优化 Dashboard 聚合查询
- 为 Plaza feed 和高成本查询引入缓存策略
- 优化图片加载和媒体卡片性能

## 推荐迭代顺序

## 迭代 1：录入体验

核心目标：降低记录成本，提升记录后的奖励感。

交付内容：

- Unified Quick Add 升级
- 统一媒体状态流转
- 元数据补全与默认项优化
- 保存后的里程碑反馈

成功信号：

- 平均记录耗时下降
- 通过 Cmd+K 创建的记录占比提升
- 单用户一周内重复记录次数提升

## 迭代 2：个人价值

核心目标：让用户为了“回看自己”而回来。

交付内容：

- Dashboard 周报 / 月报回顾卡片
- 月目标系统
- 热力图与统计卡片联动增强
- 周 / 月 / 年时间浏览

成功信号：

- Dashboard 回访频率提升
- 周留存提升
- 月目标创建与完成率提升

## 迭代 3：社交发现

核心目标：让 Plaza 从“可看”升级为“值得逛”。

交付内容：

- Plaza feed ranking
- 更丰富的动态卡片
- 轻互动与收藏
- 公开主页增强

成功信号：

- Plaza 浏览深度提升
- 从 Plaza 进入个人主页的点击率提升
- 由 Plaza 触发的收藏 / 想看类动作增加

## 当前最值得马上做的事

如果下一步只能做一个重点功能，优先考虑下面两个方向。

### 方案 A：Dashboard 月度回顾

适合目标：提升留存与个人价值感。

原因：

- 能直接增强当前 Dashboard 和热力图的价值
- 能让已有用户更快感受到“我为什么继续用”
- 是目标系统、年度回顾和分享能力的前置能力

### 方案 B：Plaza Feed 排序升级

适合目标：拉开产品差异，强化发现体验。

原因：

- 能让 Plaza 从公开列表变成真正的特色能力
- 为后续轻社交和发现机制提供基础
- 和当前 `src/lib/plaza-feed.ts` 的演进方向天然契合

综合建议：

- 如果近期更看重产品差异化，优先做 Plaza feed ranking
- 如果近期更看重留存，优先做 Dashboard 月度回顾

结合当前产品结构，Plaza feed ranking 是更有辨识度的下一步。

## 可直接拆分的 PR 级任务

### `feat/plaza-feed-ranking`

- 定义可解释、可调参的 feed 评分模型
- 引入时间衰减与质量权重
- 为排序逻辑补单元测试和样例数据

### `feat/dashboard-monthly-recap`

- 新增 Dashboard 月度回顾卡片
- 展示完成数、活跃天数、平均评分、Top 类别
- 为后续中英文文案扩展预留结构

### `feat/unified-quick-add`

- 把四类媒体录入整合到统一快录流程
- 在一次交互中完成搜索、选择、状态、评分、日期
- 优先利用最近使用行为做默认推荐

### `feat/media-status-flow`

- 为各媒体类型补齐统一生命周期状态
- 同步更新筛选、统计和卡片展示
- 验证对现有记录兼容

### `chore/logging-cleanup`

- 替换剩余 `console.*`
- 将相关模块统一接入 `createLogger`

## 建议跟踪的产品指标

### 核心使用

- 周活跃用户的人均记录数
- 通过快速录入完成的记录占比
- 每周活跃用户数

### 留存与习惯

- 7 日 / 30 日回访率
- 用户月均活跃天数
- 连续记录参与率

### 回顾价值

- 人均 Dashboard 回顾卡片浏览次数
- 目标创建率
- 目标完成率

### Plaza 健康度

- 人均 Plaza 访问次数
- 来自 Plaza 的点赞 / 收藏 / 想看类动作数
- Plaza 卡片到公开主页的点击率

## 维护建议

- 每当一个大方向从“规划中”进入“开始实施”，同步更新本路线图
- 具体实现细节放在 issue、PR 或技术设计文档中，这份文档保持产品视角
- 在首个回顾系统或 Plaza 排序系统落地后，重新评估优先级与投入比例
